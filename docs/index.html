Comprehensive Plan Land Use

For more information about this layer please see the GIS Data Catalog.A comprehensive plan is a generalized; coordinated land use policy statement of the governing body of a county or city that is adopted pursuant to the Washington State Growth Management Act. The CPLU designations are defined in the King County Comprehensive Plan and so designated in order to implement the plan's land use policies. All incorporated areas are purged from the published layer as King County does not have planning jurisdiction in those areas. CPLU designation boundaries are tied to cadastral features. When cadastral features are adjusted to improve positional accuracy the CPLU boundaries must also be adjusted.

Sensitive Area Ordinance Streams

For more information about this layer please see the GIS Data Catalog.Streams are defined in the Sensitive Areas Ordinance (SAO) as those areas of King County where surface waters produce a defined channel or bed. A defined channel or bed is an area that demonstrates clear evidence of the passage of water and includes but is not limited to bedrock channels, gravel beds, sand and silt beds and defined-channel swales. The channel or bed need not contain water year-round. This definition is not meant to include irrigation ditches, canals, storm or surface water runoff devices or other entirely artificial watercourses unless they are used by salmonids or used to convey streams naturally occurring prior to construction in such watercourse.

Tree Point Index

This layer provides an approximate inventory of tree center points for King County in 2021. Tree points were derived through an automated process using 2021 lidar, Ecopia land cover, and NAIP imagery. This layer provides an estimate of tree location and tree height from lidar, tree type (evergreen vs decidious) from lidar intensity, and vegetation health from imagery using NDVI.The points in this layer have not been QA/QC'd or field verified. This layer is not as accurate as a ground inventory would be. However, there are ~101,000,000 trees in King County, so this analysis provides a feasible approximation of tree location and density at a fraction of the cost and effort. Because there are so many features, the layer has been split into tiles of about 1 - 2 million points. Use the Tree Point Index polygon layer to identify which tiles you need to cover your area of interest. All tree point features are turned on by default, but restricted to a max of 1:10,000 scale for visibility. If you don't see tree points when you load this layer, zoom in further and wait a few seconds for the layer to render. To improve performance, turn off tree point tile layers you don't need.For detailed information on how this layer was derived, please see the History of Building- Vegetation Height, & Tree Canopy at King County storymap.For lidar intensity values, 0-120 = Deciduous, 120-200 = Conifer, 200-255 = Other. This is an estimated range.NDVI values range from -1 to 1, with values closer to 1 indicating lush green vegetation.Tree height is measured in feet above the bare earth DEM. A “tree” in this layer is any vegetation taller than 10 feet.  No updates are planned for this layer.

This layer provides an estimate of tree location and tree height from lidar, tree type (evergreen vs decidious) from lidar intensity, and vegetation health from imagery using NDVI.The points in this layer have not been QA/QC'd or field verified. This layer is not as accurate as a ground inventory would be. However, there are ~101,000,000 trees in King County, so this analysis provides a feasible approximation of tree location and density at a fraction of the cost and effort. Because there are so many features, the layer has been split into tiles of about 1 - 2 million points. Use the Tree Point Index polygon layer to identify which tiles you need to cover your area of interest. All tree point features are turned on by default, but restricted to a max of 1:10,000 scale for visibility. If you don't see tree points when you load this layer, zoom in further and wait a few seconds for the layer to render. To improve performance, turn off tree point tile layers you don't need.For detailed information on how this layer was derived, please see the History of Building- Vegetation Height, & Tree Canopy at King County storymap.For lidar intensity values, 0-120 = Deciduous, 120-200 = Conifer, 200-255 = Other. This is an estimated range.NDVI values range from -1 to 1, with values closer to 1 indicating lush green vegetation.Tree height is measured in feet above the bare earth DEM. A “tree” in this layer is any vegetation taller than 10 feet.  No updates are planned for this layer.

Methodology

This tool audits a curated subset of King County's GIS Open Data portal (gis-kingcounty.opendata.arcgis.com) - not the full catalog of several hundred datasets. The subset spans different geometry types (polygon/line/point), publishing patterns (a single layer vs. a tiled family of layers), and a mix of infrastructure, hazard, and environmental data.

Where the data comes from:

  • Portal-wide metadata: King County's own DCAT-US 1.1 catalog feed (data/fetch_catalog.py) - a standard, publicly documented open-data format, no authentication required.
  • Per-dataset checks: each target dataset's own ArcGIS FeatureServer REST endpoint (data/audit_datasets.py), throttled to 1 request/second and limited to a bounded sample (up to 500 records, or the service's own maxRecordCount if smaller) - never a full download.

Checks run (all deterministic, no LLM involved - see data/checks.py): Metadata completeness, Freshness, Geometry validity, CRS / extent sanity, Attribute null rates, Hub link alive.

How this page stays current: a scheduled GitHub Actions workflow (.github/workflows/refresh-audit.yml) re-runs the fetch and audit scripts daily and republishes this page - see the "Last audited" timestamp at the top.

Known limitations:

  • This is a curated subset (~18 datasets), not the full portal - a production version would need the checks engine hardened against far more schema variety before running unattended across everything King County publishes.
  • Data-level checks run on a bounded sample, not the full dataset.
  • Freshness and null-rate thresholds are simple fixed heuristics, not an official data-quality standard - they surface candidates worth a human look, not certified findings.
  • The CRS/extent sanity check is a rough King County bounding-box proxy, not an exact spatial-containment check.
